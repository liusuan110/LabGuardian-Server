## Key findings

Headline (post R8 fix, 2026-05-18): **false_pass = 0.0000 on every (profile × split) cell** — the rule path is now sound across the entire sim→real risk surface we've modelled.

1. **R8 closed the Wire-drop production bug.** Pre-fix the round-trip alone cost 7-15% false_pass even on clean noise (test 0.0714, val 0.1435) because `_payload_raw_pin_edges_cur` and `current_netlist_v2_to_graph` both skipped `component_type=="Wire"`. Stray jumper wires bridging VCC↔GND were invisible to the rule path. The fix keeps Wires as regular component nodes; `_critical_extra_items` now correctly counts their contribution to role-critical net degrees. ``extra_wire_bridge`` went from **1.0000 → 0.0000** false_pass on val under every profile.
2. **R6 noise profiles are absorbed cleanly.** Going from clean → low → high on test produces zero change in any metric. Comparator + advisor robust to pin-confidence noise, ID renames, dropped IC subtype, and stray wire clutter.
3. **High-noise on val leaks 11% false_fail.** Only one cell is non-zero: val × high → ``rule_false_fail_rate = 0.1138``. All concentrate on ``pin_swap_symmetric``. Root cause: the ``rename_components`` operator (``R1`` → ``Resistor_001``) interacts with how the rule comparator pairs symmetric passive pins. Not a regression — it's the cost of swapping false_pass for false_fail. Real production rarely renames so aggressively; if it does we'll catch it via R5 nightly.
4. **SEAL F1 unchanged across profiles** (0.9953 test, 0.9794 val). The GNN advisor is independent of these noise axes — its features come from port-level graph structure, not from component IDs or net labels.

## Interpretation guide

- **clean** = on-disk round-trip overhead only. Any gap vs the synthetic baseline measures the cost of going through `_hcg_to_netlist_v2 → build_from_netlist_v2` (instead of in-memory reconstruction). Production code always goes through netlist_v2, so the **clean column is the realistic floor**, not the synthetic baseline.
- **low** = pin-confidence noise only — labels, IDs, subtypes all preserved. Failure here means the comparator depends on perfect detector confidence (shouldn't, since the rule path ignores confidence).
- **high** = worst-plausible prod noise (low confidence + no labels + renamed IDs + no IC subtype + stray wires). This is the **actual sim → real risk surface**. The delta from clean to high tells you where prod data hurts the comparator most.

Use the per-perturbation table to localise which error families regress as noise increases — those rows point at the rule subsystem to harden next.
